# The savegame compatibility stamp, asserted by every iOS build (D-084, D-110).
#
# This is OPENQ4_SAVEGAME_COMPAT_SOURCE_HASH as produced by upstream's
# tools/build/generate_savegame_compat_header.py run against PRISTINE upstream
# at the commits in UPSTREAM.pin:
#
#   python3 vendor/openQ4/tools/build/generate_savegame_compat_header.py \
#       --project-root vendor/openQ4 --game-stage-root vendor/openQ4 \
#       --header-out /dev/stdout
#
# scripts/gen-savegame-compat-header.sh recomputes it on every build and fails
# loudly if it differs, so the value written into new saves is a function of
# the pin and never of our patched trees or of build order.
#
# What it gates changed with the v0.13.2 pin (D-110). Up to 227ee810 the engine
# (framework/Session.cpp) and both game modules (gamesys/SaveGame.cpp) refused
# any v2 save whose stamp was not this exact string. From v0.13.2 saves carry a
# v3 payload whose compatibility gate is the payload VERSION plus the wire ABI
# (and a build floor of 661); a stamp mismatch on a v3 save is only a developer
# print. Every v2 save — i.e. every save made by 0.1.0.64 and earlier — is
# refused outright by upstream's design ("no v2 snapshot has a verified
# decoder"), independently of this value.
#
# v0.14.000 (D-116): new saves carry payload v4; v3 payloads (every save made
# by openQ4-ios 1.0.0) still load — the engine and both game modules accept
# versions 3 and 4, the stamp stays advisory, and the build floor is still 661.
# The game sources are in-tree now, so --game-stage-root is vendor/openQ4 too
# (exactly what upstream's meson passes), which is why the file count moved.
#
# v0.14.1 (D-118): new saves carry payload v5 (portable: explicit field
# widths, wire ABI "le64-portable1", loadable by every 64-bit LE openQ4 build).
# v3 (1.0.0) and v4 (1.0.0.1/1.1.0) payloads still load; within a version the
# LAYOUT is read by the payload's build number (SaveGameReleases.h), and the
# stamp below is what identifies our two shipped hash-derived build numbers to
# overlay 0031, which reads them as builds 878 and 1574. The stamp is still
# advisory for acceptance; the build floor is now 640. From this pin the iOS
# build number is the real upstream commit count (UPSTREAM.pin OPENQ4_BUILD).
#
# v0.15.0 (D-122): payload v5 unchanged (OPENQ4_SAVEGAME_PORTABLE_VERSION 5),
# floor 640 unchanged, layout thresholds unchanged except one new GUI revision
# (guis/hud.gui at build 2438 -> savecompat/hud_r4.gui for older payloads). Our
# v0.14.1 saves (build 2390, payload v5) are read by that real build number;
# v4/v3/v2 keep 0031's mappings (1574 / 878 / 639). New saves stamp build 2636.
# The stamp stays advisory for acceptance.
#
# UPDATE THIS FILE ONLY WHEN UPSTREAM.pin MOVES. Never update it to silence a
# build failure: a dirty vendor tree or a changed generator is a bug to find.
